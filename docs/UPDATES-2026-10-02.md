## 2. 网关的两个关键行为（排障时先看这两条）

1. **token 只存在内存里**：dsh 每次重启都会换 token，网关必须收到一次
   `POST /__gw_register` 才能替访客换取会话 cookie。所以"网关起来了但没人注册"
   的表现是：密码正确 → 停在"网关尚未收到本次启动的 token"页面。
   自检命令：`curl -k https://<gateway>/__gw_health` → 看 `token registered via …`。
2. **会话 cookie 比 token 长寿**：cookie 由 dsh 用**持久化**的签名密钥签发、绑定 authority，
   所以 dsh 重启后旧会话仍然有效；但网关进程自己重启会丢掉内存里的 token
   （cookie 也随之需要重新换取）。这条解释了"同一台机器上，一个入口还好、另一个入口
   突然要求 token"的现象。

## 3. 与华为负一屏那条链路的关系

认证网关解决"怎么进 GUI"，负一屏卡片解决"地址与 token 怎么送到手机"。
两者唯一的耦合点是：**卡片里的局域网地址必须带本次 token**，而免 token 入口只推短地址。
卡片侧的实现与端到端注意事项见 `dsh-harmonyos-hiboard` 仓库的
`docs/UPDATES-2026-10-02.md`。
